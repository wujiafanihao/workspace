## 1. 动机

后端搜索与首页同步仍在规划时，前端需要先把 **信息架构与页面骨架** 立起来，避免阻塞视觉与交互评审。  
因此阶段一用 **mock JSON**（形状对齐后端合同），阶段二再换成自建 API。

---

## 2. 目标

### 2.1 阶段一（本计划当前焦点）

- Vue3 页面：**首页 `/`**、**搜索结果 `/search`**
- 组件拆分清楚（见 design）
- mock fixtures 与搜索/首页计划中的字段同构
- **不绑定真实后端**；README/设计写明切换方式

### 2.2 阶段二（后续，非本阶段必达）

- 将 mock 替换为 `GET /api/home`、`GET /api/search`
- 错误态 / 空态与合同错误码对齐

---

## 3. 范围 / 非范围

### 3.1 范围内（阶段一）

| 项 | 说明 |
|----|------|
| 路由 | `/`、`/search`（query 带 `word`） |
| 页面与组件清单 | design 列出 |
| Wireframe / 布局说明 | 可 markdown 描述 |
| mock fixtures | 首页聚合 + 搜索 list |
| 切换说明 | mock → API 的配置点 |

### 3.2 非范围（阶段一）

| 项 | 说明 |
|----|------|
| 真实 API 联调 | 阶段二 |
| 用户登录 / 编辑词条 | 另计划 |
| SSR/SEO 专项 | 可后续 |
| 业务源码仓库初始化以外的后端 | 本目录只写计划文档；若另开前端仓实现，不在 baiduWiki 塞 FastAPI |

> 硬规则（原）：本任务在 `baiduWiki/plans` **只写文档**；不要在 baiduWiki 下创建 Vue/FastAPI 应用源码。
>
> **修订说明（2026-09-19）**：用户要求阶段一前端实现于 `baiduWiki/web/`（Vue 3 + mock，无 FastAPI）。plans 仍只放文档；应用源码在 `web/`，不在 `plans/`。

---

## 4. 验收标准（阶段一）

1. plan/design 写明 **「阶段一 MAY mock」**（本文已写；design 再强调）。
2. 路由与组件列表完整。
3. mock JSON 形状对齐搜索 design + 首页聚合键。
4. todo 仅含页面/线框/mock；**无**「绑定真 API」必做项。
5. `check.md`：`status: in_progress`。

---

## 5. 风险

| 风险 | 缓解 |
|------|------|
| mock 与合同漂移 | 字段变更时同步改三份 design + fixtures 说明 |
| 阶段一过度实现真请求 | todo 明确禁止；check 不勾联调项 |
| 范围扩到详情页 | 非范围；需要则新开计划文件夹 |

---

## 6. 阶段一成功时用户能看到什么

- 打开首页：各模块区块有占位/mock 内容（结构像真首页）。
- 搜索：输入词 → 结果列表页展示 mock list（或基于 query 过滤 mock）。
- 开发者：改一处配置即可在阶段二切到自建 API。
